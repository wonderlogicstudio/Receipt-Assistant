# 전체 표와 팝업 검수

2026-10-19. 합성 시안을 먼저 전달한 뒤 사용자 "시안대로 진행" 응답을 받고 구현했다. 기존 미커밋 작업은 보존했고 커밋·푸시는 수행하지 않았다.

## 1. 생성·수정 파일

- 화면: `app/ui/review_view.py`, `app/ui/receipt_form.py`, `app/ui/summary_view.py`.
- 검증: `tests/test_receipt_form.py`, `tests/test_review_view.py`.
- 문서: README, PLAN, SPEC, CHECKLIST, CHANGE_CONTROL, DECISIONS, 이 기록.
- 예상 시안과 실제 화면 증거는 Git에서 제외한 로컬 작업 폴더에 보관했다. 실제 고객 파일은 사용하지 않았다.

## 2. 구현 기능

업로드 결과 전체를 통일된 표로 먼저 확인하고 행 선택 또는 표 아래 선택으로 상세 검수 팝업을 연다. 표에는 사용일자·상호·사업자번호·할인·공급가액·부가세·최종결제금액·결제수단·중복의심·검수상태만 표시한다. 표의 숫자 정렬을 유지하면서 금액을 콤마로 표시하고 미표기는 `—`, 명시된 0원은 `0`으로 구별한다.

팝업은 좌측 원본·우측 서식으로 구성한다. 각 비교 영역을 스크롤해도 아래 이전/다음/닫기/저장/저장 후 다음 버튼은 비교 영역 밖에 유지한다. 원본의 확대 기능과 기존 안전한 경로 검증을 유지한다. 파일명·추가 추출값·검토 항목은 접힌 상세정보 안에 둔다.

입력 중인 초안은 영수증별로 현재 세션에 유지한다. 저장 전에는 표와 엑셀에 반영하지 않으며 닫기·다른 영수증 이동 뒤 복원한다. 입력을 마치고 다른 칸으로 이동하거나 Enter를 누르면 금액을 콤마로 정리한다. 잘못된 문자·구분자·소수와 기존 안전 정수 범위 초과는 저장을 막는다. 저장 시 이전 엑셀 다운로드를 해제하여 재생성하도록 한다. 상태 필터의 검토필요만 보기와 확인/제외 기준 진행 건수를 제공한다.

## 3. 주요 구조

추가 패키지 없이 기존 Streamlit 표·팝업과 pandas Styler를 사용한다. `ReceiptRecord`·Parser·Provider·Validator·Exporter·DB 계약은 유지한다. 전체 표는 nullable 정수를 유지하고 표시 형식만 바꾼다. 기존 공통 `format_display_amount`와 레코드 병합 함수를 재사용한다.

팝업 진입 시 필터 결과의 ID 순서를 보관한다. 저장 후 상태 필터에서 현재 행이 사라져도 이 ID 순서로 이전/다음을 연결한다. 입력 위젯과 별도인 초안 사전을 두어 위젯이 해제된 뒤 재열기에도 복원한다. 입력 손실을 줄이기 위해 바깥 클릭/ESC로 팝업을 닫지 않고 닫기 버튼을 제공한다. 닫은 뒤 필터와 선택 위치를 유지한다. 새 로그인·동기화·DB 초안 저장은 추가하지 않았다.

## 4. 테스트 명령

```powershell
.venv-ocr\Scripts\python.exe -m compileall -q app tests
.venv-ocr\Scripts\python.exe -m pytest -q -p no:cacheprovider --tb=short --disable-warnings
```

## 5. 테스트 결과

- compileall 통과. 전체 pytest **822 passed / 2 skipped / 100 warnings**, 38.81초.
- 기존 802개 통과 기준 대비 20개 테스트 사례를 추가했고 기존 단일 서식 검증은 전체 표→팝업 검증으로 전환했다. 경고는 기존 Paddle/protobuf 관련이며 실제 OCR opt-in 테스트는 실행하지 않았다.
- 검증 내용: 전체 10건/필수 열/내부 정보 비노출, 숫자형과 0/누락 구분, 콤마·음수·잘못된 입력, 선택 외 레코드 보존, 엑셀 반영, 초안과 저장값 분리, 이전/다음/닫기/마지막 저장 후 다음, 상태 필터 후 이동 대상 보존과 다운로드 해제.
- AppTest는 닫은 팝업의 테스트 트리를 보존하는 한계가 있어 초안 재마운트 검증은 새 테스트 클라이언트의 위젯으로 수행했다. 실제 닫기·재열기는 Chrome에서 별도로 검증했다.
- 실제 앱에서 합성 이미지 10개를 Mock OCR로 처리했다. 표의 행 선택이 아래 선택과 연결되고 원본 이미지와 팝업이 정상 표시되는 것을 확인했다. 입력 `123456`을 닫기 뒤 재열었을 때 `123,456`으로 복원했고, 저장 전 표는 `33,000`을 유지했다. 저장 후 다음에서는 첫 행이 `123,456`으로 바뀌고 다음 대상은 `33,000`을 유지했다.
- 한 영수증을 확인완료로 저장한 뒤 진행 1/10건과 검토필요만 보기의 9건 표시를 확인했다. 동일한 Mock 합성 이미지여서 중복의심 Y가 표시되지만 자동 제외하지 않았다. 기존 엑셀 생성·처리 이력 저장은 브라우저 검증에서 실행하지 않았다.
- 작업 시작 사본/해시 대비 이번 UI·테스트·문서 이외 기존 파일의 의도하지 않은 변경이 없으며 OCR/Parser/Exporter/Core/Validator/History 계층과 의존성이 보존됐다.

## 6. 문서 동기화

README와 SPEC의 기본 화면 설명을 전체 표·팝업으로 갱신하고 PLAN/CHECKLIST/CHANGE_CONTROL/DECISIONS를 동기화했다. 데이터 모델·버전·엑셀 시트/컬럼·테스트 표준 명령은 바꾸지 않았다.

## 7. 남은 리스크

초안은 이번 작업 세션용이며 서버 재시작·새 브라우저 세션까지 보존하지 않는다. 긴 원본과 추가 입력은 팝업 각 영역 안에서 스크롤한다. 기본 확대 미리보기는 기존 크기 제한을 유지하며 모바일 화면과 PDF 원본 미리보기는 이번 변경의 검증 범위가 아니다.

실제 고객 파일의 OCR 품질은 평가하지 않았다. 현재 결제금액 의미·포인트/복합결제 구분은 기존 계약이며 이 작업에서 새 계약으로 전환하지 않았다. 금액을 직접 변경한 경우의 기존 최종결제금액 반영 경로도 유지했다. 검수값은 사용자가 확인해야 하며 확인완료 표시는 전문가 판단을 의미하지 않는다.
