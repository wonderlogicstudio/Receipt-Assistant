# 로컬 PaddleOCR 후보 계약·좌표 후속 점검

2026-10-19. 사용자 첨부 16장을 로컬 PaddleOCR로 처리했다. 매장별 정답을 등록해야 사용하는 제품이 아니다. 개발용 비교 자료는 인식 경로에 전달하지 않으며, 기존 기준은 변경하지 않았다. 100% 목표는 미달이다.

## 범위와 보존

수정 전 `app/`, `tests/`, 필수 문서의 167개 파일을 로컬 `.venv/ocr-contract16-before`에 해시와 함께 보존했다. 기존 작업 트리의 사용자 변경은 유지했다. PaddleOCR 2.7.3 / Paddle 2.6.2 / Python 3.11.9 / GPU 1개, 같은 16개 원본과 실행 설정을 사용했다. 유료 API·모델 변경·새 의존성·정답 주입·금액 역산은 추가하지 않았다.

기존 평가 자료와 대응하는 사진은 11장, 88항목이다. 값 있는 항목은 71개이고 나머지 17개는 미표기 기대값이다. 새 5장용 평가 자료의 값 기입은 자동 승인 검토에서 근거·승인 확인 부족으로 거부됐다. 이 파일을 다른 방법으로 작성하지 않았다. 따라서 **16장 128항목 정확도**를 주장하지 않는다. 추가 사진은 원본과 관측 결과 대조로만 구분한다. 모두 개발에 사용했으므로 새로운 미사용 검증 사진도 아니다.

## 남긴 변경

- Parser: 숫자·영문 단어 조각이 들어간 명시 상호를 일반 상품/메타데이터 필터로 버리지 않는다. 사용할 수 없는 첫 후보를 건너뛰며, 정규화 가능한 후보끼리 충돌을 판정한다.
- Parser: 명시 거래 총액을 더 큰 지급 후보로 덮어쓰지 않는다. 포인트 사용·잔여·적립을 자동 할인액으로 합치지 않는다. 빈칸과 명시 0원은 유지한다.
- Provider: 괄호·통화 기호·세금 라벨 변형을 정규화한다. 가로 세액 표는 같은 페이지의 라벨과 아래 숫자 열을 연결하고 관측 숫자 조각 전체를 보존한다. 글자 상자의 1픽셀 겹침도 허용한다.
- Provider: 명시 받은 돈·거스름돈을 거래 총액으로 승격하지 않는다. 상호의 다음 전화 필드 경계와 짧은 지역명/지번 주소를 보완한다.
- Provider: 회전 보완 이미지와 확대 부분 이미지의 좌표를 원본 방향의 좌표로 복원한다. 잘린 영역의 오프셋·확대율도 반영한다. 후보 값과 출처 ID는 바꾸지 않는다.
- 평가 실행기: 전화번호 형식의 사업자번호, 잘못된 날짜, 동일 이미지 중복 채점을 OCR 초기화 전에 거부한다. 형식 검사가 사람의 의미 판독을 대신하지는 않는다. 10자리 형식만 맞는 잘못된 번호까지 검출한다고 주장하지 않는다.

판매금액/거래금액 옆에 부가세가 있다는 이유만으로 공급가액으로 재분류하는 실험은 제거했다. 기존 필드 의미를 유지한다. 합성 사례는 실제 매장과 다른 이름·번호·금액을 사용한다.

## 남은 오류와 다음 조치

| 대상 | 남은 문제 | 확인된 원인/다음 조치 |
|---|---|---|
| D01 | 공급가액·부가세 누락 | 라벨/숫자 분할과 영역 인식 실패. 각 숫자 영역의 실제 관측 회복 필요 |
| D02 | 상호·공급가액 누락 | 제목 상호 영역 인식과 기울어진 세액 행 연결. 숫자 재인식 좌표 근거도 다시 확인 필요 |
| D03 | 지점명 불일치 | 브랜드명만 남고 지점 정보 누락. 원본 상단 영역 재인식 필요 |
| D04 | 총액 오답·세액 누락 | 세액 숫자는 일부 읽지만 분산 라벨/숫자 행 연결과 총액 자릿수 읽기가 실패 |
| D05 | 공급가액 누락 | 판매금액을 공급가액으로 임의 치환하지 않음. 필드 의미/실제 표시 근거 확인 필요 |
| D15 | 상호 첫 글자 불일치·공급가액 누락 | 기존 기준의 첫 글자 차이를 일치 처리하지 않음. 거래금액을 공급가액으로 임의 치환하지 않음 |
| 추가 사진 | 할인 일부·상호·재촬영 총액 오류 | 첫 후보만 남기는 약한 후보 경로와 접힘/기울기에서 이웃 행 숫자를 차용하는 경로가 남음 |

OCR 엔진 한계라고 일괄 분류하지 않는다. D04처럼 숫자 자체는 일부 읽힌 경우에는 연결 로직 과제도 남는다. Provider의 기존 약한 후보 경로가 이미 채운 값은 누락 재인식만으로 고쳐지지 않는 한계가 있다.

좌표는 StandardOCRResult에 보존하지만 현재 Parser context의 후보 맵은 값 목록으로 축약한다. Parser에서 출처·좌표별 경쟁 후보를 직접 비교하는 전체 개선은 완료되지 않았다. 포인트 사용액과 복수 카드/현금 구성도 기존 단일 필드에 억지 저장하지 않는다. 해당 확장은 모델·엑셀·카드대조 영향을 정리하는 별도 변경 제안이 필요하다.

전체 998 passed / 3 skipped(경고 1,094개). 마지막 판매금액 재분류 제거 뒤 해당 Provider/Parser/평가/엑셀 회귀 85 passed / 1 skipped로 다시 확인했다. OCR 환경의 관련 테스트는 83 passed였고, 이후 추가한 세액 열 경계 사례는 기본 환경에서 통과했다. 실제 16장의 표준 OCR 결과를 앱 처리 함수에 넣어 128개 필드의 Parser/앱 결과 일치와 표·서식·기존 8개 시트 엑셀의 금액 보존을 별도로 확인했다. 이것은 **128개 인식값의 정답 일치 검증이 아니다**.

브라우저에서 업로드·미저장 검수가 없는 새 작업 상태를 확인하고 사전 안내 후 프로젝트 실행기로 로컬 앱을 재시작했다. 소유 프로세스 확인을 허용한 실행에서 8501 running, HTTP health 200/ok를 확인했다. 브라우저의 이번 처리 Provider는 PaddleOCR Local, GPU 모드는 선택 상태이며 cuda_compiled=True/device=gpu_0다. 전역 설정의 기본 Provider는 바꾸지 않았다. 화면 증거는 로컬 `output/contract16_runtime.png`다.

브라우저 파일 선택 자동화가 시간 초과로 중단되어 재업로드→팝업→실제 다운로드의 새 화면 대조는 완료하지 못했다. 앱 처리 함수·표·검수 서식·엑셀 메모리 산출물 대조와 구분한다. 이전 DB·엑셀·과거 OCR 값은 자동 정정하지 않는다. 커밋·푸시는 하지 않았다.
