## 3. 구조와 적용하지 않은 실험

기존 이미지 → Provider → StandardOCRResult → StandardOCRParserContext → ReceiptRecord → 검수·엑셀 구조를 유지했다. SDK 객체나 Provider raw response를 Parser에 새로 전달하지 않았다. Adapter·모델·스키마·버전·엑셀 8개 시트 계약은 바꾸지 않았다.

누락 공급가액/부가세가 있고 총액 후보가 있는 경우에만 겹치는 구간으로 다시 읽는다. 최대 8구간이며 경계의 중복은 원본 좌표 중심으로 제거한다. 기존 필드 값은 덮어쓰지 않고 누락 세액 후보만 추가한다. 새 후보의 출처 블록을 충돌 없는 ID로 함께 연결한다. 재인식 실패 시 원래 completed 결과를 유지하고 민감하지 않은 경고 코드만 남긴다. 누락값을 계산하거나 세무 의미를 추정하지 않는다.

상호 라벨 보정은 알려진 필드명에만 적용한다. 특정 상호·사업자번호·사진 파일명을 추가하거나 정답을 조회하는 코드가 아니다. 기존 정답 주입 재발 방지, 파일명 불변성, 판독 기준 미전달 테스트도 계속 통과했다.

실험은 운영 설정을 바꾸지 않고 로컬에서 비교했다. 당시 코드 단계에 따라 결과가 다르므로 단계 간 수치를 합산하지 않는다.

| 실험 | 해당 단계의 결과 | 적용 여부 |
|---|---|---|
| 검출 해상도 1920 → 3840 | 이전 코드와 동일한 31/47, 다른 필드 퇴행 발생 | 미적용 |
| 전체를 분할 OCR 결과로 교체 | 당시 33/47, 기존 상호·번호 퇴행 | 전체 교체 미적용. 누락 세액만 보완하는 방식으로 제한 |
| 명암 보정 전체 교체 | 추출 수정 단계 34/47 대비 32/47 | 미적용 |
| 검출 임계값 완화·dilation | 36/47이었지만 기존 상호·총액 퇴행 | 미적용 |
| 검출한 행 이미지 전체 재인식 | 27/47, 여러 필드 퇴행 | 미적용 |

모델/의존성을 새로 설치하거나 외부 OCR·LLM API를 호출하지 않았다. GPU는 기존 CUDA 지원 환경에서 사용 가능함을 확인했다.

## 5. 검증 결과

- 기본 Python 환경: **894 passed, 2 skipped**, 기존 datetime 등 경고 1,034건. 기본 테스트는 실제 OCR·모델 다운로드·외부 API를 실행하지 않는다.

## 7. 남은 위험과 미검증 범위

- 남은 양성 실패 9개와 빈칸 결제수단 오탐 1개. 상호·숫자·라벨 광학 인식, 날짜 라벨 복원, 안내문 문맥 처리가 더 필요하다. 특히 부가세 3/6은 자동 처리 품질로 충분하지 않다.
- 같은 8장에 반복 개발한 결과다. 별도 사진·전체 69장·모바일·대량 배치·세무 실무 적합성을 검증한 정확도가 아니다.
- 이 실행에서 전체 8장 시간은 약 30.03초 → 45.85초였다. 첫 초기화 항목을 제외한 평균은 약 1.92초 → 3.89초. 재인식으로 느려졌으며 엄밀한 성능 벤치마크는 아니다.
- Provider가 위치 관계로 만든 후보나 한 블록 내 명시 세액이 없는 표준 context는 다음 블록 숫자를 세액으로 차용하지 않는다. 실제로 다음 블록에 세액이 있더라도 후보가 없다면 미확인으로 남을 수 있다. 기존 text wrapper는 호환을 유지한다.
- 넓은 금액·날짜 조각 휴리스틱이 모두 사라진 것은 아니다. 근거가 부족한 다른 오인식 가능성이 남으며 검수가 필요하다. 확인한 한 개의 무라벨 원 금액 추측 함수는 제거했다.
- 원본·기존 DB·엑셀·세션은 수정하거나 재시작하지 않았다. 과거 결과가 자동 정정되는 것은 아니다. 커밋·푸시·배포도 하지 않았다.
