# 파일럿 가이드

## 파일럿 목적

영수증 OCR 엑셀 비서 MVP가 실제 업무에서 세무사 전달용 정리 파일을 만드는 데 도움이 되는지 확인한다. 이번 파일럿은 세무 판단이나 신고 제출 가능 여부를 검증하지 않는다.

## 파일럿 대상

| 대상 | 검증 포인트 |
|---|---|
| 세무사 또는 세무사 사무실 직원 | 엑셀 구조, 필수 컬럼, 검토필요 사유, 원본파일명 추적 방식 |
| 1인 사업자/프리랜서 | 업로드와 검수 난이도, 기존 정리 시간 대비 효율, 비용항목 추천의 참고 가치 |
| 소상공인/쇼핑몰 운영자 | 카드내역과 영수증 정리 편의성, 월별/비용항목별 요약의 업무 적합성 |

## 준비물

- 개인정보 제거 또는 더미 처리된 영수증 이미지/PDF
- 개인정보 제거 또는 더미 처리된 카드 사용내역 CSV/XLSX
- 테스트용 `.env`
- 실행 가능한 로컬 Python 환경
- 피드백 기록 템플릿

실제 카드번호 전체, 주민번호, 전화번호, 민감정보가 포함된 파일은 사용하지 않는다.

## 테스트 절차

1. 앱 실행: `streamlit run app/main.py`
2. `새 작업` 메뉴 확인
3. 파일 업로드
4. `파일 저장 및 처리` 실행
5. 검수 화면 확인
6. 일부 값 수정
7. 필요한 항목 제외 처리
8. `표준 엑셀 생성`
9. `엑셀 다운로드`
10. 엑셀 파일 열기
11. `처리 이력` 메뉴에서 방금 작업 조회
12. 상세 화면에서 영수증/카드내역/export 파일 확인
13. 기존 엑셀 파일 재다운로드 확인
14. `설정` 메뉴에서 provider, 보관기간, 저장소/DB 상태, cleanup dry-run 요약 확인
15. 결과물 만족도와 불편한 점 기록

## 실제 OCR 대표 확인 케이스

파일럿에서는 가능한 범위에서 아래 케이스를 더미 처리된 파일로 확인한다. 실제 민감값이나 실제 고객 파일은 사용하지 않는다.

| 케이스 | 확인 포인트 |
|---|---|
| 할인 후 0원 결제 | 할인전금액, 할인금액, 최종결제금액, 실제결제금액, 총금액 0 표시와 검토필요 사유 |
| 상품권/포인트/카드결제 혼재 | 최종결제금액과 실제결제금액 분리, 금액판단기준, 금액검토사유 |
| 부가세 미표기 영수증 | 명시 공급가액/부가세는 비워 두고 참고 추정값만 별도 표시 |
| 카드 승인번호 포함 영수증 | 승인번호나 긴 숫자가 할인금액 또는 실제결제금액으로 들어가지 않는지 |
| 수량이 많은 품목형 영수증 | 수량 1, 3, 10 등이 금액 후보로 들어가지 않는지 |
| 민감문구 포함 가능 영수증 | WiFi PW, 비밀번호, 카드번호 전체 등 실제 값 미표시와 category 표시 |
| Azure OCR 실제 처리 | 전체 OCR 원문이 아니라 제한된 Parser context line만 반영되는지 |

## 성공 기준

정량 기준:

- 업로드 → 다운로드까지 오류 없이 완료
- 샘플 20건 기준 10분 이내 검수 가능
- 필수 엑셀 시트가 모두 생성
- 검수 수정값이 엑셀에 반영
- 할인/부가세 참고 추정/민감문구 감지 컬럼이 의도대로 표시
- 엑셀 생성 후 처리 이력 목록에 작업 표시
- 상세 화면에서 기존 엑셀 재다운로드 가능

정성 기준:

- 세무사에게 전달하기 쉬운 구조인지
- 검토필요 사유가 이해되는지
- 비용항목 추천이 참고용으로 유용한지
- 기존 수작업 대비 시간이 줄어드는지
- 처리 이력과 설정 화면이 파일럿 운영에 도움이 되는지

## 실패/중단 기준

- 앱 실행 불가
- 파일 업로드 불가
- 처리 후 검수 화면 미표시
- 엑셀 생성 불가
- 다운로드 파일 열기 불가
- 처리 이력 저장 또는 조회 불가
- 민감정보가 포함된 테스트 파일 발견
- 전체 로컬 경로나 OCR 원문 전체가 화면/엑셀에 노출
- 민감문구 실제 값이 화면/엑셀/피드백 문서에 노출
- 승인번호, 수량, 푸터 숫자가 금액으로 반복 오인식

## 개인정보 주의사항

- 실제 카드번호 전체 사용 금지
- 주민번호 사용 금지
- 전화번호와 민감정보는 실제 값 사용 금지
- 실제 고객 파일명 기록 금지
- 전체 로컬 경로 기록 금지
- OCR 원문 전체를 피드백 문서에 붙여넣지 않기
- 실제 OCR 문제를 공유할 때는 원문 전체 대신 비민감 요약, 화면 컬럼명, 더미 raw_text 형태로 기록하기

## 파일럿 결과 기록 방법

파일럿 1회마다 `docs/pilot_feedback_template.md`를 복사해 기록한다. 기록에는 대상 유형, 사용 파일 종류, 건수, 오류 위치, 검수 소요 시간, 엑셀 만족도, 처리 이력/재다운로드 만족도, 개선 요청을 남긴다.

## 다음 개선 판단 기준

- 같은 혼란이 2명 이상에게 반복되는가
- 검수 시간이 목표보다 길어지는 원인이 명확한가
- 엑셀 컬럼 수정 요구가 반복되는가
- 처리 이력이나 재다운로드가 실제 업무에서 쓰이는가
- mock 기준 테스트와 실제 OCR provider 테스트의 차이가 큰가
