## 3. 구조와 모바일 재사용 경계

이미지 → Provider → StandardOCRResult → StandardOCRParserContext → Parser → 검증·중복·카드 후보 → 사용자 검수 → ExcelExporter 흐름을 유지한다. Provider 원본 응답을 파서에 새로 전달하지 않았다. ReceiptRecord와 기존 엑셀 8개 시트·컬럼은 유지한다.

모바일은 OCR 어댑터를 별도로 만들고 표준 결과 계약과 검증·검수·엑셀 흐름을 재사용하는 방향이다. Paddle 전용 이미지 보완 규칙 전체를 모바일에 옮기는 방식은 권하지 않는다. 모바일 앱은 이번 범위에 포함하지 않았다.

시각 판독 기준은 운영 코드 밖의 로컬 파일이다. 평가 도구는 이미지 해시를 확인하고 **OCR을 끝낸 뒤** 기대값과 비교한다. 기대값을 바꾸어도 Provider 호출 인자가 바뀌지 않는 테스트가 있다.

## 4. 테스트와 반복 평가 명령

```powershell
.venv\Scripts\python.exe -m compileall -q app tests scripts
.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider
.venv-ocr\Scripts\python.exe scripts/evaluate_local_receipts.py --reference output/quality_refs/visual_reference.json --gpu
```

로컬 `output/quality_refs/visual_reference.json`에는 파일명, SHA-256, 직접 판독한 필드가 있다. 원본과 기준은 Git에서 제외한다. ‘완불’은 결제수단으로 특정할 수 없어 제외했다. 일반 ‘금액’과 ‘판매금액’도 공급가액인지 확정할 수 없어 해당 두 항목을 제외했다. 면세·과세 물품가액은 정해진 추출 라벨 의미와 대조했으며 차감·세율 계산이나 세무 판단을 하지 않았다.

결과 `output/quality_runs/local_evaluation.json`에는 익명 ID와 match / missing / different만 기록한다. 원문 전체, 실제 상호·사업자번호·금액, 파일명·전체 경로를 결과에 넣지 않는다. 외부 OCR/LLM API는 호출하지 않는다.

평가 종료 코드 0은 채점 항목 일치, 1은 인식 실패 또는 불일치, 2는 기준·해시·실행 오류다. 기본 pytest에는 실제 OCR·모델 다운로드를 추가하지 않았다.

## 5. 검증 결과

최종 기본 환경 Python 3.13: **874 passed / 2 skipped**. 실제 앱의 Python 3.11 OCR 환경 핵심 회귀: **138 passed**. compileall과 `git diff --check`도 통과했다. datetime 관련 기존 경고 등은 남아 있다. 기본 테스트에서 실제 OCR·네트워크·모델 다운로드는 실행하지 않는다.

GPU 확인: Paddle 2.6.2 / PaddleOCR 2.7.3, CUDA 지원, GPU 1개, `Place(gpu:0)` 텐서 연산 성공. 별도로 실제 이미지 8장을 로컬 GPU OCR로 반복 처리했다. 파일명을 평가용 이름으로 바꾸어 처리했으며 고정 정답표는 운영 코드에서 제거한 상태다.

최종 판독 기준은 64개 가능 항목에서 불확실한 3개를 뺀 61개다. 이 중 원본에 식별 가능한 값이 있는 47개만 따로 집계하여 빈칸 일치가 인식률처럼 보이지 않게 했다. 표의 상호 비교는 공백·문장부호만 무시하며 지점 누락은 불일치다.

|---|---:|
| 상호 | 4 / 8 |
| 사업자번호 | 6 / 7 |
| 사용일자 | 6 / 8 |

실제 값 기준 **31 / 47**이며 할인금액은 실제 할인 사례가 없어 양수 할인 인식률을 평가하지 않았다. OCR 실행 완료는 8 / 8이지만 **품질 검증 통과를 의미하지 않는다**. 빈칸까지 포함한 일치는 44 / 61이다. 종료 코드 1은 이러한 불일치가 남았다는 뜻이며 실행 중단이 아니다.

원본에서 직접 확인한 뒤 같은 사진으로 수정·재측정했으므로 이 수치는 개발 표본의 진단 결과다. 독립된 미사용 이미지에 대한 일반 정확도로 홍보할 수 없다. 현재 품질은 상품화에 충분하지 않다.

## 6. 문서·데이터 보존

모델·schema / validator 버전·엑셀 출력 계약을 유지했다. 파싱 정책 변경은 이 날짜의 SPEC / 변경관리와 회귀에 남겼다. 기존 미커밋 변경, 원본 이미지, 기존 DB와 출력 엑셀은 자동 수정·삭제하지 않았다. 과거의 정답 주입·사전 치환이 적용된 결과는 재검수가 필요하다.

## 8. 추천 커밋 메시지

`fix: remove receipt answer injection and harden OCR integrity`

기존 사용자 변경과 이번 수정을 검토해 작은 단위로 나누는 것이 좋다. 테스트 통과만으로 자동 커밋·푸시하지 않았다.

수정하지 않은 기존 Exporter, 검수 팝업·서식, 실행기, OCR 표준 모델·어댑터 등 13개 파일은 작업 전 백업과 SHA-256이 일치했다. 일회성 진단 스크립트 8개는 제거했고 로컬 이미지 판독 기준과 재사용 평가 도구만 남겼다.
