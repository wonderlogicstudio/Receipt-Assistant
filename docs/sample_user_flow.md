# 샘플 사용자 흐름

## 1단계: 앱 실행

사용자 작업:

```bash
streamlit run app/main.py
```

기대 결과:

- 브라우저에서 앱이 열린다.
- 사이드바 메뉴에 `새 작업`, `처리 이력`, `설정`이 표시된다.

문제가 생겼을 때:

- `pip install -r requirements.txt` 실행 여부를 확인한다.
- 기본 데모는 `.env`가 없어도 mock provider로 실행 가능해야 한다.

## 2단계: 파일 준비

사용자 작업:

- 개인정보 제거 또는 더미 처리된 영수증 이미지/PDF를 준비한다.
- 개인정보 제거 또는 더미 처리된 카드 사용내역 CSV/XLSX를 준비한다.

기대 결과:

- 확장자는 JPG, JPEG, PNG, PDF, CSV, XLSX 중 하나다.

문제가 생겼을 때:

- 지원하지 않는 확장자는 이번 MVP에서 제외한다.
- 실제 카드번호 전체, 주민번호, 전화번호가 들어간 파일은 사용하지 않는다.

## 3단계: 파일 업로드

사용자 작업:

- `새 작업` 메뉴에서 파일을 선택한다.

기대 결과:

- 영수증 파일과 카드 사용내역 파일을 함께 업로드할 수 있다.

문제가 생겼을 때:

- 파일 크기와 확장자를 확인한다.
- 파일명을 간단하게 바꿔 다시 시도한다.

## 4단계: 처리 실행

사용자 작업:

- `파일 저장 및 처리`를 누른다.

기대 결과:

- 처리 중 버튼이 비활성화된다.
- 진행 상태가 표시된다.
- OCR/Parser 결과와 카드 사용내역 parser 결과가 생성된다.

문제가 생겼을 때:

- Azure OCR 사용 시 네트워크와 API key 설정을 확인한다.
- 카드내역 컬럼명이 인식되지 않으면 CSV/XLSX 헤더를 확인한다.

## 5단계: 검수 테이블 확인

사용자 작업:

- `3단계: 검수` 영역의 테이블을 확인한다.

기대 결과:

- 사용일자, 상호, 금액, 비용항목 추천, 최종 비용항목, 검수상태, 검토사유를 확인할 수 있다.
- 할인전금액, 할인금액, 최종결제금액, 실제결제금액, 금액판단기준, 금액검토사유를 확인할 수 있다.
- 명시 부가세와 참고 추정 공급가액/부가세가 구분되어 표시된다.
- 민감문구가 감지된 경우 실제 값이 아니라 감지 여부와 유형만 표시된다.

문제가 생겼을 때:

- 검토필요 건이 많으면 OCR provider와 샘플 품질을 확인한다.
- 비용항목 추천은 참고용이므로 필요한 경우 직접 수정한다.
- 최종결제금액과 실제결제금액이 다르면 영수증 원본을 확인하고 필요한 경우 총금액을 직접 수정한다.

## 6단계: 오류/검토필요 건 수정

사용자 작업:

- 날짜, 상호, 금액, 최종 비용항목, 메모 등을 직접 수정한다.

기대 결과:

- 수정값이 현재 세션의 검수 결과에 반영된다.

문제가 생겼을 때:

- 숫자 컬럼에는 숫자만 입력한다.
- 테이블 편집 후 다른 셀을 클릭해 반영 여부를 확인한다.

## 7단계: 제외 처리

사용자 작업:

- 정리내역에서 제외할 항목은 포함 여부 또는 검수상태를 제외로 표시한다.

기대 결과:

- 제외 항목은 정리내역 시트에서 빠지고 제외내역 시트에 기록된다.

문제가 생겼을 때:

- 제외 사유나 메모를 남겨 엑셀에서 확인한다.

## 8단계: 엑셀 생성

사용자 작업:

- `표준 엑셀 생성`을 누른다.

기대 결과:

- 엑셀 bytes가 생성된다.
- 처리 이력 DB에 ProcessingJob이 저장된다.
- export 파일이 `data/outputs` 하위에 저장된다.

문제가 생겼을 때:

- 오류 메시지의 단계가 엑셀 생성인지 확인한다.
- 저장 실패 경고가 있더라도 다운로드는 가능할 수 있다.

## 9단계: 엑셀 다운로드

사용자 작업:

- `엑셀 다운로드`를 누른다.

기대 결과:

- `receipt_summary_YYYYMMDD_HHMMSS.xlsx` 형식의 파일을 받을 수 있다.

문제가 생겼을 때:

- 브라우저 다운로드 차단 여부를 확인한다.
- 파일 확장자가 `.xlsx`인지 확인한다.

## 10단계: 엑셀 파일 확인

사용자 작업:

- 다운로드한 엑셀 파일을 연다.
- 필수 시트와 수정값 반영 여부를 확인한다.

기대 결과:

- 정리내역, 월별요약, 비용항목별요약, 검토필요, 카드대조, 원본파일목록, 처리로그, 제외내역 의미의 시트가 생성된다.
- 전체 로컬 경로, OCR 원문 전체, raw JSON 전체가 보이지 않는다.
- 할인금액, 참고 부가세 추정값, 민감문구 category는 명시값과 구분해 확인할 수 있다.
- 할인 후 0원 결제 건은 자동 제외되지 않고 검토필요 사유와 함께 확인할 수 있다.

문제가 생겼을 때:

- 파일이 열리지 않으면 다시 생성하고 다운로드한다.
- 민감정보가 보이면 즉시 기록하고 파일럿을 중단한다.
- 승인번호, 수량, 푸터 숫자가 금액으로 보이면 해당 화면 컬럼과 더미 예시를 기록한다.

## 11단계: 처리 이력 확인

사용자 작업:

- `처리 이력` 메뉴로 이동한다.
- 방금 생성한 작업을 선택한다.

기대 결과:

- 목록에서 작업이 보인다.
- 상세 화면에서 ReceiptRecord, CardTransaction, ExportFile 요약을 볼 수 있다.
- 기존 엑셀 파일 재다운로드가 가능하다.

문제가 생겼을 때:

- DB 저장 경고가 있었는지 확인한다.
- export 파일이 삭제된 경우 재다운로드 안내 메시지를 확인한다.

## 12단계: 설정 화면 확인

사용자 작업:

- `설정` 메뉴로 이동한다.
- OCR provider, 보관기간, 저장소 상태, DB 상태, cleanup dry-run을 확인한다.

기대 결과:

- key 값과 endpoint 전체 URL은 보이지 않는다.
- cleanup dry-run은 실제 파일을 삭제하지 않는다.

문제가 생겼을 때:

- 설정 화면 오류는 파일럿 기록에 남긴다.
- 실제 삭제 버튼이 보이면 파일럿을 중단한다.
