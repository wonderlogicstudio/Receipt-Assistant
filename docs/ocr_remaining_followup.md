# 남은 OCR 9개 불일치·결제수단 오탐 후속 개선

2026-10-19. Ponytail full. 기존 미커밋 변경은 보존하고 Provider 수정·검증 후 Parser 수정·검증을 별도로 진행했다. 이전 평가는 [실패 16개 후속 기록](ocr_failure_followup.md)이다.

**결과: 같은 개발 사진 8장의 값 있는 필드는 38/47 → 39/47이다. 기존 일치 항목의 퇴행은 0개이며, 별도 결제수단 오탐 1개를 제거했다. 47/47에는 도달하지 못했다.** 개선에 사용하지 않은 4장의 필드 일치는 20/25 → 20/25로 같았다. 새 사진의 정확도 향상을 입증한 결과가 아니다.

## 1. 생성·수정 파일

- `app/ocr/paddle_provider.py`: 누락 날짜에 한정한 좁은 구간 재인식. 기존 세액 재인식의 간격·병합 대상을 유지한다.
- `app/parser/receipt_parser.py`: 법령 안내문과 붙어 있는 단독 결제수단 조각을 결제 증거에서 제외한다.
- `tests/test_paddle_detail_fallback.py`: 누락 날짜 복원, 기존 값·0원 보존, 날짜 재인식의 세액 격리, 실패 진단 비노출 회귀.
- `tests/test_receipt_identity_integrity.py`: 분리·역순 법령 조각, 실제 현금/카드 보존, 떨어진 안내문과 구분하는 회귀.
- `scripts/evaluate_local_receipts.py`, `tests/test_local_ocr_evaluation.py`: 문자·숫자가 전혀 없는 손상/빈 문자열 기준을 OCR 전에 거부한다.
- README, PLAN, SPEC, CHECKLIST, CHANGE_CONTROL, DECISIONS 및 이 보고서.

판독 기준·익명 평가 결과·일회성 실험은 Git에서 제외된 `output/quality_refs`와 `output/quality_runs`에서만 관리했다. 원본 사진과 정답을 제품 코드나 테스트 fixture에 추가하지 않았다. 실험 스크립트는 최종 소스에 포함하지 않는다.

동일 사진의 남은 양성 오류는 **8개: 누락 6개, 비어 있지 않은 오답 2개**다. 47개 외 결제수단 오탐은 1개에서 0개가 됐다. 읽을 수 없는 사진이라고 판정한 것이 아니라, 사람이 판독할 수 있어도 현재 모델·시도한 방식에서 안정적으로 회복하지 못했다는 뜻이다.

## 3. 구조·변경 경계

이미지 → Provider → StandardOCRResult → StandardOCRParserContext → ReceiptRecord → 검수·엑셀 구조를 유지한다. 모델·선택 의존성·Adapter·보안 필터·스키마/버전·ExcelExporter는 변경하지 않았다. 정답 기준은 결과를 얻은 뒤 비교하며, 실제 파일명을 인식에 전달하지 않고 `evaluation.jpg`를 사용한다.

기존 누락 세액 재인식은 최소 1,000px 구간과 최대 8구간을 그대로 사용한다. 총액 후보가 있고 날짜가 없으면 별도로 최소 500px 구간, 최대 8구간을 읽어 **날짜 후보만** 병합한다. 매우 긴 사진은 높이/8을 간격으로 삼아 호출을 제한한다. 두 재인식이 모두 필요하면 최대 16구간이며 그 밖의 기존 회전/정규화 fallback도 별도로 존재한다. 같은 엔진·EXIF 방향 처리·겹침·좌표 복원·출처 ID 병합을 재사용한다. 기존 후보는 덮어쓰지 않고 재인식 실패도 기존 결과를 유지한다.

적용하지 않은 실험:

- 모든 세액에 250/500px 분할 적용: 날짜를 회복하지만 기존 상호·번호의 교체 퇴행과 새 세액 오탐 가능성이 있어 전체 교체·세액 병합을 폐기했다.
- 검출 임계값 완화와 영역 확장 비율 조정: 0과 상호를 회복하지 못하고 사업자번호 누락도 생겼다. 운영 엔진 설정은 바꾸지 않았다.
- 명시 세액 라벨 오른쪽 영역, 기울기 보정, 검출 없는 인식: 안정적인 0 증거를 얻지 못해 추가 기능으로 넣지 않았다.

Ponytail 기준으로 효과가 확인되지 않은 실험·설정·추가 의존성을 제품에 넣지 않았다.

## 7. 남은 위험·미검증 범위

- **47/47 미달.** 같은 8장을 반복 개발한 39/47이며 일반 인식 정확도가 아니다. 별도 사진 결과도 충분하지 않다.
- 날짜 보완은 효과가 있었지만 남은 0·상호·합계·세액 라벨 문제는 해결하지 못했다. 다른 모델/엔진 또는 추가 영역 재인식이 실제로 개선하는지는 별도 증거가 필요하다.
- 별도 사진에서 할인·최종결제액·세액 불일치 5개가 확인됐다. H01 최종금액/할인 오답, H02 명시 할인 0 누락, H03 공급가액 누락/부가세 오답이다. 이 사진들의 결과를 보고 다시 수정하면 해당 자료도 개발 자료가 되므로 새로운 별도 평가 집합이 필요하다.
- 단독 결제수단 조각 바로 옆에 법령 안내문이 있는 경우는 보수적으로 누락될 수 있다. 자체 금액이 있는 행·사이에 금액이 있는 행·typed Provider 후보는 보존한다. 결제수단의 카드/신용카드 등 명칭 표준화는 이번 수정에 포함하지 않았다.
- 최대 호출 수 제한은 있으나 날짜 없는 긴 사진은 더 느려진다. 전체 69장·PDF·모바일·대량 동시 처리·실무 적합성은 검증하지 않았다.
- 원본·기존 DB·과거 엑셀·사용자 세션은 수정/재시작하지 않았다. 과거 결과가 자동 정정되지 않는다. UI 변경·외부 API·커밋·푸시·배포는 하지 않았다.
